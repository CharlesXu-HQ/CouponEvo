# App 促活实验数据接入约定

当前只使用固定 CSV 离线实验。真实业务数据尚未提供，下面是接入时需要落地的字段约定，不代表已有这些字段或实验结论。

| 用途 | 推荐字段 | 要求 |
| --- | --- | --- |
| 随机化单位 | `user_id` | 一次实验每人一行；同一用户不得跨训练、验证、测试集。 |
| 随机分组 | `assigned_coupon` | 记录分配而非是否领券或核销；对照组和发券组均保留。提供真实分组概率、方案或分配日志引用。 |
| 促活 | `active_7d` 等 | 先确定触达后观察窗口和活跃定义，再映射为 manifest 的 `active`。 |
| 收入或毛利 | `revenue_7d`、`gross_margin_7d` | 两者可只提供其一；若提供毛利，声明是否已扣优惠券成本。 |
| 优惠券成本 | `coupon_cost_7d` | 有实际核销成本时映射为 `coupon_cost`，对照组必须为零；没有时可明确标注假设发送成本，或仅使用人数预算。 |
| 特征 | 干预前画像 | 只能使用分组前可用的字段；给出每个特征的记录时间与分组时间可启用 `--strict-data` 逐行检查。 |
| 现行规则 | 独立候选代码 | 将现行发券选择逻辑冻结为候选文件，最终测试集用 `--compare-candidate` 与 Agent 冠军逐用户配对比较。 |

数据治理人员先把固定文件及 [manifest 说明](../README.md#dataset-manifest)准备好，再审查处理概率、口径、特征时点和现行规则。Agent 可改候选算法和预算内的选择策略，也可在 `feature_gaps.md` 记录缺失画像；它不能改冻结数据、分组概率或评估器。最终报告应同时看促活、成本、净收益及其配对区间。没有这些字段时，只报告公开数据实际支持的指标。
