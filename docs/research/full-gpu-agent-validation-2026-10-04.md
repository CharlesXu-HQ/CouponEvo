## Agent 搜索与最终结果

Starbucks 使用 `cost=0.03` 的预算，以购买转化为固定目标。Agent 读取基线验证报告，提出把 EconML T-Learner 的 PyTorch 岭回归结果模型换成 MLP，写明可测量的预期，然后在 GPU 沙箱中训练、预测、评估。它得到验证集策略效果点估计 `0.003667`，基线为 `0.003312`；相对基线的同用户配对区间跨零。`high/max` 分析把特征时间仅有声明记录为**待核验风险**，没有误判为已证实泄漏。反思判为 `inconclusive`，候选仍可晋级；Agent 随后主动停止进一步搜索。GPU 上的候选训练代码实际将模型和批次移到 `cuda`，测试集运行记录的 CUDA 峰值分配为 76,356,096 字节。

独立测试切分的 2,000 次用户级配对 bootstrap 结果见[Starbucks 最终 JSON](starbucks-full-agent-final-2026-10-04.json)：候选相对岭回归基线的购买转化增量差值为 **−0.000118/人**，95% 区间 **[−0.001656, 0.001420]**。相对随机发券的差值为 `0.001538/人`，区间 `[−0.000591, 0.003667]`。这次自动调优没有显示可靠的测试集提升。数据中 `0.15` 是每位被选中用户的固定发送成本假设；没有实际核销成本、毛利或 App 活跃标签，不能报告真实净收益或促活效果。运行日志：`runs/starbucks-full-agent-v2-20261004/journal.json`。

Hillstrom 使用 `count=0.2` 的预算，以访问 `visit` 为固定目标。Agent 提出正则化的 PyTorch MLP，并在 GPU 上完成训练与预测，候选验证分数 `0.013847` 低于基线 `0.016897`。指标分析、预期对照和反思完成后，Agent 停止搜索并保留基线。最终测试切分结果见[Hillstrom 最终 JSON](hillstrom-full-agent-final-2026-10-04.json)：基线相对随机选择的访问增量差值 `0.004927/人`，95% bootstrap 区间 `[−0.004223, 0.015022]`，跨零。该数据是邮件触达，不是优惠券；没有券成本或毛利，不能用于净收益结论。运行日志：`runs/hillstrom-full-eligible-agent-20261004/journal.json`。

再次启动相同 Starbucks 任务时，`runs/starbucks-full-experience-20261004/journal.json` 的 `experience` 只含前一次正式搜索 `starbucks-full-agent-v2-20261004` 的验证集经验。Agent 据此提出残差 MLP，并在 GPU 上完成验证集评估与反思。该次仅验证经验读取及后续决策，**没有重复使用测试切分进行模型选择或最终评估**。

## 验证中发现并修复的问题

第一次真实运行显示：分析器把 `feature_timing=declared_only` 标为泄漏疑虑，但搜索器把疑虑当成“已证实泄漏”阻断候选。现在 `feature_leakage` 同时记录 `flag` 与 `confirmed`，疑虑仍触发 `max`，只有 `confirmed=true` 才阻断晋级。第二次运行显示旧版的错误反思被新搜索读作经验；现在任务增加 Agent 工作流源码指纹，评审或晋级逻辑变化后不会读取旧经验。

本地测试 `101` 项通过、`1` 项跳过；目标机同样 `101` 项通过。上述两个正式搜索、最终测试、经验复用均在目标机执行。公开数据的特征时间缺少逐行证据，Starbucks 的成本是固定假设；这些限制已留在报告中。工程排错时曾先对同一 Starbucks 测试切分评估基线，之后才完成修复后的候选评估，因此这里的测试结果是固定切分的诊断证据，不应被写成严格预注册的模型发现。可靠的业务结论仍需真实券成本、活跃标签及新的独立实验。
