## 首次运行：失败保留

基线在 GPU 上完成，但未产生通过校验的新候选：

1. 首次提案请求触发默认 180 秒墙钟截止。
2. 仅在诊断 driver 将默认请求截止改为 600 秒后恢复；后续请求约 135.5 秒返回。它本身未超过 180 秒，不能据此断定延长截止解决了所有请求问题。
3. 返回标记为 `stop` 的最终内容缺少 JSON 闭合符，触发自动格式重试。
4. 随后的提案用 `switch` 引用没有 `model_design` 的 seed，被组件来源校验拒绝。
5. 下一份提案正确使用 `initialize`，但导入不在宿主允许范围的 `copy`、`typing`，再次被拒。

这些是提案/集成失败，不是完成的模型实验。没有人工修正候选，也没有把失败提案计为效果提升。

修复仅涉及宿主反馈：首次初始化说明、明确允许导入范围、具体错误模块名，以及恢复搜索时保留当前阶段最近两条提案错误。导入允许范围、候选代码、数据和评估器均未放宽。修复通过 52 项相关回归测试；随后在独立搜索目录重新验证。

诊断 driver 的 600 秒默认请求预算是本次运行覆盖项，产品默认仍为 180 秒；分析函数显式指定的截止不受默认值覆盖影响。原始失败记录与新搜索分开保存。

第二次运行又遇到组件反思的 10,000 token 截断，以及后续提案的 32,768 token 截断。操作员只调整响应预算，分别设为反思 20,000、提案 65,536，然后从同一日志恢复；标准 JSON、组件、代码、结果校验仍执行，未修正 Agent 返回文本或候选。这是人工恢复后的行为验证，不能称为发布版本在默认配置下无人干预跑通。输出预算也影响推理可用空间，因此结论仅适用于记录的配置，不能保证低预算下行为相同。

提高预算在官方 API 范围内：查询时 DeepSeek 文档列出 thinking 模式默认输出预算为 64K。[Chat Completions API](https://api-docs.deepseek.com/api/create-chat-completion/) 本次只保存最终内容、用量及响应状态，不保存推理正文。

## 第二次运行

首个候选通过初始化与代码校验，在 GPU 上训练，并完成 high/max 分析及组件反思。第二个候选未落地；计划上限为四个候选，实际只完成一个。最优仍是 seed。搜索因请求失败中断，没有完成 Agent 的 stop 或预算收尾；本轮也未验证跨运行持久经验加载。

| 已执行候选 | 策略 conversion 效应 | Qini | 状态 |
| --- | ---: | ---: | --- |
| seed：EconML T-learner + PyTorch ridge | 0.00331224 | 0.00253379 | 基线 |
| step-001：两臂 ArmNet，仿射跳连 + ReLU 残差，BCE、Adam、训练内早停 | 0.00295735 | 0.00189709 | 已评估、实现核验通过、反思 inconsistent |

指标按全部 eligible 验证用户归一，选中 3,381 人不能用作上述效应均值的分母。step-001 相对 seed 的同单位配对差值为 **-0.00035488**，95% 区间 **[-0.00201071, 0.00130095]**，跨零。没有观察到提升，也不能据此证明两者等价；验证集被用于探索，未做独立最终确认。

源码路径实际成立：`ArmNet.forward` 的 affine + residual → BCE 反向传播/Adam → 训练内早停恢复最佳权重 → 各臂 sigmoid → `mu1 - mu0`。候选执行约 10.17 秒，CUDA 峰值 71,618,560 字节；输出概率差一致性最大误差约 `1.0e-15`。用于模型选择的内部 10% 留出来自训练分区，未发现使用外部验证标签训练的路径。

反思将五个组件均记为 `inconclusive`、`attribution=unverified`，随后提案上下文包含这次源码、反思和结果。候选同时改变结构、损失、优化器和早停，因此不能把结果单独归因于残差网络。Agent 关于“严格包含原模型函数类”的原断言也未获证实：父模型输出为无界仿射函数，候选在输出处用了 sigmoid；实现核验通过不等于这一推理正确。

首轮没有 `reference_reads`，使用的是 Agent 原创 ArmNet。本轮不能据此声称验证了“读取 Harness 的结构代码后融入 backbone”。也没有实际运行 backbone 切换，选择性迁移尚未实测。

第二轮完整提案（API call-009）确实读取了首轮历史和反思，提出保留 BCE、Adam、早停和概率差输出，移除残差分支的局部对照。它把 backbone 字段改成了新的描述文本，因稳定标识不一致被拒。之后一次 JSON 修复仍失败，最后请求超时。另有未完成提案尝试转回 ridge 加类别编码；没有被接受或执行，不能计为模型切换。

## 运行中发现的限制

- **标识与说明混淆。** 一份完整后续提案按反思提出局部残差消融，但改写了 backbone 说明串，触发 `local preserves estimator/backbone`。该提案没有执行，不能计为局部结构实验。后续需要让稳定标识和当前结构说明各自明确，减少本可执行的假设被格式问题阻塞。
- **结构化输出成本高。** 多次最终 JSON 未闭合或输出被截断；仅增大 token 上限不能保证合法提案。后续建议分开研究决策、组件账本与代码生成，保持来源与校验契约。
- **缺少来源复用实测。** 组件 schema 和真实代码执行成立，但尚无真实成功的参考源码融合或跨 backbone 迁移证据。

反思截断修复已另提交为 `a34613c`：最多三次请求，仅 `length` 扩容，格式/语义修复共享次数，其他错误不盲重试。相关 28 项测试通过。它没有被写入正在运行的冻结搜索，本次不能宣称该新提交已经无人干预完成真实 GPU 多轮搜索。
