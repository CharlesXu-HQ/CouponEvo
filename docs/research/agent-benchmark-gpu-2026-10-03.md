本记录保留旧版本的实验结果；当前代码只复用同一数据集版本和评估任务的经验，不应按本文步骤重现实验。

2026-10-03 在 `Linux GPU host` 的 RTX 5090 上，使用 DeepSeek `deepseek-flash`、`high` 迭代和按需 `max` 复核，分别对两份公开随机试验做两轮候选代码搜索。候选训练与评估在无网络 Docker 容器中运行；镜像 ID 为 `sha256:ec2754fb9f85d20060360fad9165fd272ea3d84c07e9301757c7bb42c62d6095`。Starbucks 固定成本预算为每名候选用户 0.03，Hillstrom 固定触达人数比例为 0.2；两阶段在各自任务内使用相同初始候选、种子与提案数。

两组搜索每组两次提案均成功评估。测试集区间使用 500 次逐用户配对 bootstrap。Starbucks 的跨任务经验方案在这一次测试集比较中为正；Hillstrom 的区间跨零。两项任务目标与单位不同，不能汇总原始分数或据此断言经验机制稳定改善算法。DeepSeek 的随机生成、同一批测试数据上的多次比较和只有两份数据集，都限制了结论。Hillstrom 是邮件营销而非发券；Starbucks 无 App 活跃标签或实际券成本。

收紧候选输入后，又用最终代码重放两组冠军的测试集配对比较，差值与上表逐位一致。容器运行时检测到 CUDA 张量分配：Starbucks 经验候选峰值 76,388,864 字节，Hillstrom 经验候选峰值 72,287,232 字节；对照候选也通过相同的 CUDA 分配检查。这证明运行中使用了 GPU 张量，但模型结构和因果解释仍需代码审查。

每份搜索日志在目标机 `$PROJECT_ROOT/runs/benchmark-rsi-20261003/`。`plain/` 与 `experience/` 的日志保存每步候选、验证分数与最终报告；`paired/` 保存两方案同一测试集的配对比较，`summary.json` 保存总体结果。跨任务经验只从**其他数据集已完成搜索的验证集步骤**提取假设与分数变化；最终测试集报告没有传给 Agent。两组测试结论都应结合候选代码与数据时点进行人工复核。
