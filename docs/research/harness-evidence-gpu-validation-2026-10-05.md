# 证据约束改造及 GPU 验证

## 这次改了什么

ModelEvoHarness 增加宿主事实引用、实验数据请求证据校验、归因条件和非阻塞审计建议。CouponEvo 接入实际预处理宽度、张量形状、设备、损失及两组潜在结果的一致性检查；分析同时读取假设、父代码和差异。实现矛盾或分析失败的候选不能晋升。错误机制经验标为无效，原声明单独保留，不再作为已验证的经验。

这一校验能核对引用来源和数值契约，不能自动证明全部文字结论、特征路径或梯度路径。代码审阅仍可能误判；直接 CATE 和明确声明的排序分数也不能靠概率差值检查证明其有效性。

- 主搜索及经验回放：CouponEvo `e22c1ae9e050e14305c5600887a4900c5f0227fb`，ModelEvoHarness `478b4ec0233b2bc2368e4f8652377482c6896a55`。
- 复核修复：`5f507c1` 增加截断识别，`e3deea1` 将每个分析阶段限制为三次尝试，给截断后无效 JSON 留出格式修复机会。仅 `finish_reason=length` 增加响应预算：`high` 从 10,000 到 20,000，`max` 从 16,000 到 32,000，总 token 上限 32,768。
- 最后补充的 ModelEvoHarness `4ffa40a3b9051006c2102fca87d66513754144c7` 将函数能力推导和“观测字段不等于效果消融”的规则纳入独立 Harness，CouponEvo 同步接入；该提示补充未重跑新模型搜索。
- `913ac41` 增加整个 API 请求的墙钟截止时间（一般 180 秒，长回复 300 秒），并要求对“新结构增加表达能力”的声明推导父模型函数。旧 socket timeout 会被服务端保活延长；一次标称 300 秒的请求实际约 443 秒才失败。新截止时间限制调用方等待；读取线程在下一次读返回时关闭连接，无新字节时仍可能等待其 socket timeout。
- RTX 5090；PyTorch CUDA；完整 Starbucks CSV 共 84,534 行，不抽样。文件 SHA-256：`4d48190fd0d6a65d3874fa9a9ac79d89007579716366c2cfe140ae999088aa4f`。
- seed 42；训练 50,720、验证 16,907、测试 16,907，三个分区不相交且覆盖全部源记录。本次没有运行最终测试评估。历史工作已查看过该测试切分，不能再称其从未使用。
- 固定目标 conversion，预算 0.03/eligible 用户，发送成本假设 0.15/选中用户。数据没有实际核销成本、毛利或 App 活跃标签。

这是单版本行为检查。主搜索与回放使用相同版本；补丁验证单独记录，没有做 Harness 版本间的效果对比，也没有改写原实验日志。

## Agent 的实际选择

| 步骤 | 实验与选择依据 | 验证策略效应 | 原始运行资格 |
| --- | --- | ---: | --- |
| seed | EconML T-learner，PyTorch ridge 基学习器；7 列数值输入 | 0.00331224 | 基线 |
| 1 | 从运行观测确认没有类别展开，试 one-hot/标准化 + DCN S-learner + BCE | 0.00449518 | eligible |
| 2 | 根据首轮联合改动的归因问题，保留 18 列编码和 BCE，换成线性 treatment 交互 | 0.00496836 | eligible |
| 3 | 在第二轮上加残差 MLP，检验剩余非线性；未达到预设阈值 | 0.00414030 | blocked_analysis_error |

第一轮确实将低基数字段转为字符串后编码到 16 列，加入两个标准化字段成为 18 列；DCN 输入 19 列含 treatment。第二轮网络的输入为 `[x, x*t, t]`，宽度 37。三轮都返回了 `mu0`、`mu1` 和二者差值，数值一致性检查通过；CUDA 峰值内存均大于零。

实验方向体现了先探索交叉、再用简单模型检验归因、再检验残差分支的顺序。第一轮同时改了编码、模型、损失和训练；第二轮也改了优化器预算，因此反思保留 `attribution=unverified`。不能把指标变化单独归因于 DCN、编码或某个交叉项。

第三轮训练和评估完成，但原始 high/max 分析因响应截断失败。搜索保留了失败状态与探索性反思，没有将它晋升；最终按三轮预算停止，保留第二轮候选。**这份原始记录是三次模型评估、两次完整分析合格，不能写成三次完整闭环均通过。**

## 指标的置信边界

主搜索结束后，仅为核对比较对象，额外在相同验证集上用 GPU 重算第二轮候选对 seed 的配对差值；候选预测 SHA 与搜索中相同，没有再选择模型或使用测试集：

- 最优点估计：0.00331224 → 0.00496836，相对高 50%。
- 新策略减 seed：0.00165612，95% 区间 **[-0.00004754, 0.00335978]**。

区间跨零，并且验证集已被自适应使用。它是探索性候选，不能声称获得了独立验证的提升，也不能解释为利润或促活提升。策略差值区间跨零既不证明等价，也不能用来诊断 CATE 模型方差。

## 经验回放与数据请求

同版本、同任务的回放确实载入了三条经验，并选择线性交互方向，没有重复失败的残差分支。但它提出了错误前提：“线性 T-learner 不能表达 treatment-by-feature 异质性”。实际 seed 分别拟合两臂系数，`tau(x) = (b1-b0) + (w1-w0)^T x` 可以随特征变化。可以讨论其函数类或编码限制，不能把它说成不能表达异质性。

回放候选效应为 0.00485006，数值契约和 CUDA 运行成立，但原始分析先截断、后超时，资格为 `blocked_analysis_error`，最优仍为 seed。原始回放只能证明经验载入和方向选择，不能证明它正确理解了经验或纠正了错误前提。

两次搜索均按预算正常停止，将时点声明、假设成本和归因疑问保留为 `audit_recommendations`，没有生成无依据的数据请求。这验证了当前样本中的拒绝路径。独立 Harness 和集成测试覆盖真实缺口事实的接受路径；当前通用 CouponEvo 评估器不会凭指标未显著自动生成 `data_gap_candidate=true`，匿名数据也不能证明具体业务字段缺失。

## 修复后的独立补审

在 GPU 机器上用 `913ac41` 对已冻结的候选代码和原报告再次调用真实 DeepSeek；不重训、不重新选择模型，也不修改原搜索的日志或冠军。补审是修复验证，不是原运行自动通过的证明。

经验回放补审共三次调用，约 132 秒：`high` 与 `max` 都从父代码推导两臂函数，判定“父 T-learner 不具备异质性表达能力”的前提被反驳，返回 `implementation_check=contradicted`；后续反思为 `invalid`，技术经验保留 `attribution=unverified`，下一步转为重述假设与分离编码、link/loss 和训练的影响。原日志 SHA 未变。

主搜索第三轮补审约 321 秒完成：`high` 一次通过，`max` 经 16,000 token 截断、32,000 token 回复的 JSON 格式错误、第三次格式修复后成功，后续反思也完成。最终实现核验为 `verified`，反思为 `inconsistent`：残差 MLP 的实际实现与假设相符，但未达到预设提升阈值；只否定本次配置的预期，不推广为整个非线性模型类别无效。原日志 SHA 未变，原始 `blocked_analysis_error` 状态没有回填或伪装成当时已通过。

复核输出仍需读者检查：`max` 的部分文字将 logistic 概率差笼统称为线性对比，与其同一回复中正确写出的 sigmoid 差值不一致；反思还建议单独消融输出列，但仅增加 `mu0/mu1` 观测列、保持参与评价的 uplift 和选人规则不变，不会增加优化信息。后续通用提示已要求区分观测改动和预测/决策改动，前者先做便宜的契约检查；这项提示修改本身尚不能当成 Agent 永不再犯的实测证据。

此前补审的失败也保留在 API 事件中：服务端断连、截断、无效 JSON、客户端未创建输出目录，以及保活导致旧 socket 超时失效。截断后增加预算取得完整回复已实际发生，但不能由此推断所有提供商请求都会成功。
